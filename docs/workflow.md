# Процесс: фича или баг — от Fibery до `main`

Перенесено из RATEL SQUAD (`D:\Projects\Godot\ratel`, его `docs/workflow.md`) 2026-10-24.

**По умолчанию изменение коммитится прямо в `main`**, без карточки, ветки и PR.
Пайплайн ниже запускается только по просьбе пользователя: «создай задачу»,
«через пайплайн», назван `BOT-N` или вызвана команда `/task`. Тогда *зачем*
живёт в карточке, а ветка, коммиты и PR несут её номер, чтобы каждая сторона
находила другую.

Пайплайн ведёт команда проекта **`/task`** (`.claude/commands/task.md`):
- `/task <что сделать или починить>` заводит карточку;
- `/task BOT-N` подхватывает карточку с того шага, где она стоит;
- `/task done BOT-N` закрывает её после мержа.

Между карточкой и веткой команда вставляет план. Он пишется в карточку, и
пользователь одобряет его до первой строки кода.

## Где что

- **Fibery:** рабочее пространство `stendhal-syndrome-studio`, пространство
  **BoT**, база `BoT/Work Item`, вид *Board* (доска по состояниям). Доступ —
  только через MCP-сервер `fibery-studio` (корневой `CLAUDE.md`, «Fibery»).
  В том же пространстве лежат зеркала GDD (`/gdd-sync`) — это документы, а не
  база, и пайплайн их не трогает.
- **GitHub:** `MimusTriurus/tanks_builder`, базовая ветка `main`.
- **ID:** `fibery/public-id` карточки *N* пишется **`BOT-N`** и стоит на всём,
  что к ней относится:
  - в её имени (`BOT-N: …`) — его ставит правило *Prefix name with BOT-N*,
    когда карточка создана или переименована;
  - в имени её ветки;
  - в начале темы каждого её коммита;
  - в заголовке её PR.

  `git log --grep BOT-N` находит её коммиты, `git blame` строки даёт карточку.

### Карточка

| Поле | Значения |
|---|---|
| `BoT/Name` | `BOT-N: ` и одна строка: что изменение делает или что сломано (префикс ставит правило) |
| `BoT/Type` | Feature · Bug |
| `BoT/Area` | 3D bench · Match · Map editor · Pipeline · GDD · Tools · 2D legacy |
| `BoT/Priority` | Low · Medium · High · Critical |
| `BoT/Tags` | Performance · Gameplay · Graphics · Effects · UI · Tech debt · Tooling — о чём она, поперёк областей и эпиков; сколько подходит |
| `workflow/state` | Backlog → Ready → In Progress → In Review → Done · Won't Do |
| `BoT/Description` | шаблон ниже |
| `BoT/Branch` | git-ветка |
| `BoT/Pull Request` | URL PR |
| `BoT/Done Date` | ставит правило *Set Done Date*, когда карточка дошла до Done |
| `BoT/Epic` | эпик, к которому относится карточка, если есть |

**Области (`Area`):**
- **3D bench** — стенд `Tank3D.tscn`: модели, эффекты, доска;
- **Match** — партия `Match3D.tscn` и правила хода;
- **Map editor** — редактор карт;
- **Pipeline** — конвейер Blender (`pipeline/`);
- **GDD** — правила игры (`docs/gdd/`);
- **Tools** — инструменты и харнесс;
- **2D legacy** — устаревшая спрайтовая линия.

Крупная работа — **эпик** в `BoT/Epic` (Planned → In Progress → Done ·
Dropped), он состоит из карточек. Его план-документ лежит в `docs/` того цеха,
который он трогает (поле `BoT/Plan Doc`). В плане — находки, решения и метод.
Шаги и их состояние — это карточки, и документ называет `BOT-N` каждого шага.

Шаблон описания — **баг**:

```markdown
## Steps to reproduce
## Expected
## Actual
## Notes        (сцена, карта, флаги запуска, строки лога, снимок)
```

**Фича**:

```markdown
## Goal
## Definition of Done
## Notes        (что говорит GDD, какие docs/ читать, открытые вопросы)
```

## Шаги

1. **Карточка.** Взять карточку по её `BOT-N` или завести новую по запросу, по
   шаблону выше. Состояние — *Backlog*, или *Ready*, если делать сейчас. О
   Type/Area/Priority спрашивать, только если запрос их не говорит.
2. **Старт.** От свежего `main` — ветка `feat/BOT-N-short-slug` или
   `fix/BOT-N-short-slug`. Slug — несколько слов латиницей в нижнем регистре
   через `-`. Карточку перевести в *In Progress*, заполнить `BoT/Branch`.

   Здесь `main` часто живёт впереди `origin/main`: коммиты в него идут без
   push. Ветка от незапушенного `main` везёт эти коммиты в свой PR, поэтому
   перед стартом `main` пушится. Это решает пользователь. `pre-push` такие
   коммиты не проверяет: всё, что есть в локальном `main`, — не коммиты
   карточки.
3. **Работа.** По `CLAUDE.md` цеха: сначала его доки области.
   - Проверять тем, что есть у цеха. Стенд — снимок (`--capture`/`--sequence`)
     и `--perf`; `--selftest` — только если он есть в одобренном плане.
     Конвейер — сложить слои и посмотреть картинку.
   - В PR сказать, что прогнано и что это показало. Если проверку прогнать не
     удалось, это тоже сказать.
4. **Коммиты.** Номер карточки, затем стиль репозитория: по-русски, что
   изменение делает.

   ```
   BOT-N: Стенд: трава качается шейдером, а не на CPU
   ```

   Хуки в `.githooks/` следят за этим на ветке `feat/`/`fix/BOT-N-…` и больше
   нигде:
   - `prepare-commit-msg` ставит `BOT-N: ` в начало сообщения;
   - `commit-msg` отказывает теме без префикса или с номером другой карточки;
   - `pre-push` проверяет каждый коммит ветки, которого ещё нет на сервере
     (сделанный с `--no-verify` или клиентом без хуков).

   Merge, revert и коммиты `fixup!`/`squash!` проходят. Хуки включаются один
   раз на клон:

   ```bash
   git config core.hooksPath .githooks
   ```

   **Git LFS.** `core.hooksPath` выключает `.git/hooks`, а там стоят хуки LFS
   (`Models/**/*.glb`, `assets/Models/**/*.glb`). Поэтому `.githooks/` зовёт
   их сам: `pre-push` после своей проверки вызывает `git lfs pre-push`, а
   `post-checkout`, `post-commit` и `post-merge` — те же команды LFS. Без этого
   push отправил бы указатели без объектов. Новый хук в `.githooks/` не должен
   терять вызов LFS.
5. **Pull request.**
   - Запушить ветку и открыть PR в `main`. Заголовок — имя карточки (начинается
     с `BOT-N: `).
   - Тело PR: что изменилось и зачем, как проверено, URL карточки.
   - Карточку перевести в *In Review*, заполнить `BoT/Pull Request` и оставить
     на ней комментарий со ссылкой на PR и сводкой в две строки.
6. **Мерж.** Пользователь смотрит PR и мержит merge-коммитом, так что коммиты
   ветки остаются в `main`, а мерж называет PR.
   - Затем карточка переходит в *Done*; правило ставит `Done Date`.
   - Ветку удалить.
   - Карточка, брошенная по пути, уходит в *Won't Do* с комментарием о причине.

Claude не мержит, не делает force-push и не переводит карточку в *Done*, пока
не попросят.

## GitHub ↔ Fibery

- **Синхронизации GitHub в BoT пока нет.** В RATEL интеграция Fibery с GitHub
  зеркалит репозиторий в базы Branch, Commit и Pull Request. Правило *Link to
  Work Item by RAT-N* связывает их с карточкой по номеру. Для BoT это включается
  только в интерфейсе Fibery: интеграция GitHub в пространстве BoT на
  `MimusTriurus/tanks_builder`, затем формула и правило по образцу RATEL с
  `BOT-`. До тех пор связь — поля карточки `BoT/Branch` и `BoT/Pull Request`,
  которые заполняются руками на шагах 2 и 5.
- **PR из сессии Claude** открываются через `gh`, вход под `MimusTriurus`.
  Если оболочка запущена до установки `gh`, его нет в `PATH` — тогда
  `"C:\Program Files\GitHub CLI\gh.exe"`.
