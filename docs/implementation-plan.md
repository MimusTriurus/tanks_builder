# План реализации Board of Tanks: от GDD и стенда к играбельному бою

> Составлен 2026-09-07 по [GDD](gdd/index.md) (десять файлов, все противоречия
> C-01…C-09 закрыты, из дыр открыты только число N в U-01 и плейтесты) и по коду
> стенда `godot/` (≈87 тыс. строк C#, 8 корней сцен, `--selftest` на 1474
> проверки). Это план, а не правила: правила — в GDD, устройство стенда — в
> [godot/docs/architecture.md](../godot/docs/architecture.md).

## 1. Что есть и чего нет: сводка разбора

### 1.1. Что GDD требует от игры

Пошаговая hot-seat тактика, детерминированная в бою. Ядро — семь сущностей:

| Сущность | Из чего состоит (по GDD) |
|---|---|
| **Клетка** | уровень −1/0/1 · пол (земля, дорога, грязь, вода = глубина × высота) · препятствие на клетке (нет, лес, пожар, сгоревший лес, дым) · мина · стены на 0–6 гранях · признак рампы (гекс нижнего уровня с высокой кромкой) |
| **Юнит** | класс (LT/MT/HT/TD/HM) · сторона · клетка · курс корпуса (6) · курс башни (6, с памятью) · состояние (Активен / Горит / Плывёт / Утоплен / Подбит / Уничтожен) · засада (ось или две у MT) · набор апгрейдов |
| **Класс** | скорость в шагах (5/4/3/4/3) · мощь I–V · броня лоб/борт/корма · масса I–III · башня есть/нет · глагол (LT порядок, MT сектор, HT бульдозер, TD проход, HM навес) |
| **Ход** | п. 1–7: выбор юнита → путевое движение с побочными эффектами по клеткам → одно действие (выстрел / засада / способность) → п. 6 обновление (сгоревшие танки, лес под HT) → передача хода |
| **Раунд** | два хода; тик поля в конце: пожар и дым −1, распространение пожара, очки контрольной точки, счётчик пата |
| **Партия** | контракт вход/выход с метой · расстановка втёмную · жребий · победа: уничтожение или удержание точки · пас · пат через 4 раунда |
| **Апгрейды** | 14 принятых: 8 пассивных, 6 способностей; стаб отряда LT+ОПВТ, MT+трал, HM+шашка |

Всё это вычисляется без броска: правила выражаются как чистые функции от
состояния доски. Это главный аргумент за архитектуру ниже.

### 1.2. Что стенд уже умеет и что из этого переиспользуется

Стенд — визуализация, а не правила (U-15). Но модель доски у него уже почти
GDD-совместимая, и наведение сделано так, что игровой слой может ей управлять.

**Берём как есть или с минимальной правкой:**

| Готово в стенде | Где | Что даёт правилам |
|---|---|---|
| Гекс flat-top, odd-q, шесть направлений `EdgeHeadings = {30,90,150,210,270,330}`, `Step`, `Reverse`, `EdgeIndex`, `HeadingTo`, `Lane`, `LaneTo`, `Chain`, `FindPath` (BFS) | `HexField.cs` (статики и методы данных) | всю гексовую арифметику, луч по оси, BFS |
| Уровни −1/0/+1 (+2 = скала), рампа как гекс нижнего уровня с высокой кромкой, `Passable` (только вдоль оси, две рампы подряд нельзя, смена уровня только через рампу) | `HexField.cs:427-466`, `MapRules.cs` | ровно модель рампы GDD (U-03 сверен) |
| Два слота клетки `Foundation`/`Cover` + `CoverState`, таблица `TerrainRules` из `terrain.json` | `Terrain.cs` | пол и препятствие; `Forest`→`Burning`→`Burnt` совпадает с GDD |
| Стены — 6-битная маска граней, `Walled(from, heading)` спрашивает обе клетки ребра, `Breach` | `HexField.cs:1579-1694`, `Masonry.cs` | стены GDD один в один |
| Карта: алфавит из 14 букв, JSON `maps/*.json`, редактор с тремя вкладками, отменой и живым аудитом, `MapRules` (10 правил) | `BoardMap.cs`, `MapFile.cs`, `MapEdit.cs`, `MapRules.cs`, `MapEditor*.cs` | авторинг карт; `MapEdit` и `MapRules` почти Godot-free |
| Пять классов, `Might` I–V и `Mass` I–III, `Turreted`, порядок LT MT HT TD HM | `MovementProfile.cs` (Godot-free) | числа классов, кроме брони по зонам и шагов |
| `Gunnery.Penetration` («строго больше»), `RamLevel` («не меньше»), `Solve` (полоса огня по оси: танки, стены по рёбрам, `Screens`) | `Gunnery.cs` | ядро пробития и LoS, без уровней и зон |
| Сторона попадания: `AtlasSet.FaceFor` даёт плиту front/rear/left/right по пеленгу и курсу | `AtlasSet.cs:625` | вход для зон брони уже есть |
| Приказы как поля на `Vehicle` (`Path`, `Target`, `Mark`, `Charge`), одна машина исполнения `TankTick`, хуки `Aim`/`Launch`, три согласованных входа (клавиша, панель, MCP) | `Vehicle.cs`, `TankTick.cs`, `Main.cs` | готовый шов для четвёртого входа — контроллера хода |
| Картинка всего боевого: выстрел, трассер, попадание, рикошет (`ProcSpall`), разрыв (`ProcSlam`), пробитие (`ProcPierce`), детонация (`ProcRack`), взрыв в грунте (`SheetBlast`), пожар леса (`Wildfire`+`Grove`), обвал стены (`WallRig`), брод и ватерлиния, обломок (`Wreck`) | см. `godot/docs/combat.md`, `blast.md`, `water.md`, `wall.md` | всё, что игрок увидит |
| Самопроверка `--selftest` с фильтром по темам, MCP `bench-*` | `SelfTest.cs`, `McpBench.cs` | второй контур проверки для сцены боя |

**Чего в стенде нет (и это надо строить):**

- Ход, раунд, игрок, сторона, свой/чужой, бюджет шагов, засада, условие победы,
  зоны расстановки, контрольная точка, пас, пат — **ничего** из слоя партии.
- Состояния «Подбит», «Плывёт», «Утоплен» как игровые: у стенда одно `Wreck.Dead`;
  «Горит» — тумблер картинки без часов и урона.
- Броня по зонам: `Penetration` читает одно число `Mass`, плита не влияет.
- Рикошет как полёт дальше (`Shell` не порождает второй снаряд), проход TD,
  навес HM, минимальная дальность 1 пустой гекс, дальность 3–5.
- Таран как сдвиг: стенд мнёт оба корпуса и останавливает таранящего.
- Слои клетки: дорога, грязь, дым, мина как механика (буква `m` есть, правил нет),
  вода как глубина × высота (есть `Shallow`/`Deep` и маска воды, «высота» — через
  уровень клетки), лес на воде не запрещён редактором.
- LoS по уровням: `Gunnery.Solve` игнорирует высоту, снаряд в полёте (`Track`)
  её учитывает — два разных ответа на «видно ли».
- `dotnet test`: тест-проекта нет, единственный раннер — `--selftest` внутри движка.

## 2. Архитектурное решение

**Правила — отдельная чистая сборка на C#, без Godot. Стенд — её проигрыватель.**

```
docs/gdd/                       правила словами
godot/
  Rules/Rules.csproj            ← НОВОЕ: net8.0 class library, ни одного using Godot
  Rules.Tests/Rules.Tests.csproj← НОВОЕ: xUnit, dotnet test без движка
  TankSpriteTest.csproj         стенд; ProjectReference → Rules
  scripts/Match*.cs             ← НОВОЕ: девятый корень сцены, адаптер и проигрыватель событий
  scripts/…                     стенд как есть
```

Почему так, а не «дописать правила внутрь `Main`/`TankTick`»:

1. **GDD детерминирован и целиком выражается функциями от состояния.** Значит
   правила можно тестировать таблично, за миллисекунды, тысячами сценариев
   (`dotnet test`), а не двенадцатисекундным прогоном движка. Плейтесты PT-1…PT-6
   тоже сначала проигрываются здесь скриптом, потом на экране.
2. **Стенд непрерывный, правила дискретные.** Смешивать `delta` и шаги в одном
   объекте (`TankTick` уже 2678 строк, `Main` 6347) — значит потерять и то, и
   другое. Разделение «правила решили → стенд показал» повторяет уже принятый шов
   `Launch`/`Aim`: приказ — поле, исполнение — `TankTick`.
3. **Правило корней стенда сохраняется**: `Rules` ничего не знает о сценах,
   сцена боя знает о `Rules`, ни один разделяемый модуль стенда о `Rules` не
   узнаёт — адаптер живёт в файлах нового корня.
4. **Мета-слой потом подключится к тому же контракту** (match.md «Вход и выход
   боя»): вход — `MatchSetup`, выход — `MatchResult`, оба — данные без Godot.

Что для этого нужно от инфраструктуры: `NuGet.config` сейчас указывает только на
бандл Godot; для xUnit добавить `nuget.org` явно (машинные источники и так
применяются, но чистая машина должна собираться из файла). `.gitignore`
исключает `godot/*.sln` — solution с тремя проектами придётся либо снять из
игнора, либо держать `dotnet test godot/Rules.Tests` без sln.

### 2.1. Типы ядра (`Rules`)

Собственные типы вместо `Godot.Vector2I`, чтобы сборка была чистой; адаптер
переводит в обе стороны одной строкой.

| Тип | Содержимое | Откуда переносится |
|---|---|---|
| `Hex` (readonly record struct Col, Row) + `Dir` (0..5) | odd-q offset, `Step`, `Neighbours`, `Distance` (кубическая — в стенде **нет**, добавить), `Ray(from, dir)` (= `Lane`), `AxisTo(a, b)` (= `LaneTo`), `Opposite`, `HeadingDeg(dir)` для стенда | статики `HexField` |
| `Floor` | `Earth, Road, Mud, Water` + `WaterDepth {Shallow, Deep}`, `WaterHeight {Low, High}` | `Foundation` (Solid→Earth, Sand→Mud, Shallow/Deep→Water; Rock и Void — свойства карты, не пола) |
| `Obstacle` | `None, Forest, Fire, BurntForest, Smoke` + `int Timer` (раунды) | `Cover.Forest` + `CoverState` |
| `Cell` | `Level`, `Floor`, `Obstacle`, `bool Mine`, `byte Walls` (маска граней в порядке `Dir`), `Dir? Ramp` (высокая кромка), `bool OffBoard` | `HexFace` + маски `HexField` |
| `Board` | `Cell[]`, `Columns/Rows`, `Zones[2]` (расстановка), `ControlPoint?` (гекс + флаг «с соседями»), `Victory {Annihilation, Hold}`, `int StartPoints` | `BoardMap` + новые поля |
| `UnitClass` | `Speed`, `Might`, `Armour(Front, Side, Rear)`, `Mass`, `Turreted`, `Verb` | `MovementProfile` (Might/Mass/Turreted) + таблица classes.md |
| `Unit` | `Id`, `Side`, `Class`, `Hex`, `Dir Hull`, `Dir Turret`, `Condition {Active, KnockedOut, Sunk, Destroyed}`, `bool Burning`, `Overwatch? {Dir[] Axes}`, `UpgradeSet`, `bool ActivatedThisTurn` | новое |
| `Match` | `Board`, `Unit[]`, `Side Current`, `int Round`, `Points[2]`, `Stalemate` счётчик, `Phase {Deploy, Play, Over}`, `Result?` | новое |
| `Command` / `Event` | см. 2.2 | новое |

`Board` **не** заменяет `BoardMap`/`MapFile` сразу: на первом этапе адаптер
`BoardMap → Board` собирает клетки из существующих сеток, а недостающие слои
(дорога, грязь, зоны, точка, режим) читаются из новых ключей JSON. Перенос
`MapEdit`/`MapRules`/`MapFile` в `Rules` — отдельный этап (M6), когда формат
устоится.

### 2.2. Команды и события

Единственный вход в правила — `Match.Apply(Command) → IReadOnlyList<Event>`;
единственный способ узнать «что можно» — запросы `Match.Query`. UI и стенд
ничего не считают сами.

**Команды** (одна активация = последовательность): `Deploy(unitId, hex, dir)`,
`Ready` («В бой»), `Select(unitId)`, `Move(path: Hex[], finalTurns: Dir)`,
`Fire(hex)`, `FireIncendiary(hex)`, `Overwatch(axes: Dir[1..2])`, `Ram(hex)`,
`RamWall(dir)`, `Extinguish`, `Smoke(hex)`, `Winch(hex)`, `LayMine(hex)`,
`Repair(unitId)`, `Pass`, `EndTurn`. LT может прислать действие до `Move`.

**Запросы** (для подсветки и превью — GDD требует показывать исход до нажатия):
`Reachable(unit) → {Hex → Path[]}` (с равными по цене вариантами, п. 2),
`ShotPreview(unit, hex) → что встретит снаряд и с каким исходом`,
`OverwatchAxes(unit) → Dir[] с длиной оси`, `RamPreview(unit, hex) → ok/почему нет`,
`Abilities(unit) → доступные действия`.

**События** (то, что проигрывает стенд, и то, что проверяет тест): `Moved(unit,
from, to, dir)`, `Turned`, `Reversed`, `MineTriggered`, `EnteredWater`,
`CaughtFire`, `SmokeDissipated`, `WallBrokenByHull` (HT), `OverwatchFired`,
`Fired(unit, axis, ammo)`, `ShellHit(target, zone, penetrated)`, `Ricochet(from,
to, newAxis)`, `PassedThrough` (TD), `WallDestroyed`, `ForestIgnited`,
`KnockedOut`, `Sunk`, `Exploded(hex, neighbours affected)`, `ChainDetonation`,
`Pushed(unit, from, to)`, `SlidDownRamp`, `Extinguished`, `SmokePlaced`,
`MinePlaced`, `Repaired`, `TurnEnded`, `RoundTicked(fires, smokes, points)`,
`PointsChanged`, `MatchOver(result)`. События содержат всё, что нужно для
анимации, чтобы стенд не лез в `Match` за подробностями.

Детерминизм проверяется тестом: одна и та же последовательность команд на одной
карте даёт байт-в-байт одинаковые события; `Match` сериализуется в JSON целиком
(это же — сохранение партии и реплей для багрепортов из плейтестов).

### 2.3. Стенд как проигрыватель: новый корень `MatchRoot`

Девятый корень, сцена `Match.tscn`, наследует `SceneRoot` как шесть других.
Состав файлов (по образцу `MapEditor*.cs`):

- `MatchRoot.cs` — жизненный цикл: вход (`MatchSetup` из аргументов или из
  `Session`), сборка доски через существующие `HexField.SetRelief/SetGround/
  SetCover/SetSides`, спавн `Vehicle` на клетки юнитов тем же кодом, что `Main`
  (вынести спавн из `Main._Ready` в разделяемый `Fleet.cs`, он сегодня
  повторён в `Main` и `TankBench`), очередь событий.
- `MatchRoot.Input.cs` — жесты: ЛКМ по своему юниту = `Select`, ЛКМ по
  подсвеченной клетке = `Move` (с выбором пути при равной цене), ПКМ = `Fire`,
  двойной ЛКМ по танку = `Ram`, панель действий для остального. Пять жестов
  стенда переосмысливаются под ход, а не дополняются.
- `MatchRoot.Playback.cs` — **проигрыватель событий**: каждое событие
  превращается в приказ стенду и ждёт его конца. `Moved` → `Vehicle.Path`
  одной ногой и ожидание `!Moving`; `Fired`/`ShellHit` → `TankTick.Shoot` с
  заранее решённым исходом (стенд сегодня решает уровень урона при вылете —
  этот шов уже есть: `Send(..., Level = …)`), `Ricochet` → второй `Shoot` с
  клетки цели по новой оси, `Exploded` → `Stage3D.Rack`/`SheetBlast`,
  `Pushed` → новая нога у жертвы, `CaughtFire` → `Vehicle.Burning`,
  `ForestIgnited` → `Wildfire.Light` при **выключенном** его собственном тике
  (`Wildfire.Enabled = false`: распространение решают правила по раундам, стенд
  только красит), `WallDestroyed` → `WallRig` обвал грани. Кнопка «пропустить
  анимацию» и режим `--instant` для самопроверки.
- `MatchRoot.Hud.cs` — HUD хода: чья очередь, раунд, MP осталось, очки N,
  кнопки «Пас», «Конец хода», «В бой», панель способностей, экран передачи
  хода (hot-seat, экран закрыт до нажатия), экран результата.
- `MatchRoot.Overlay.cs` — подсветка достижимых клеток (`HexField.Highlight`
  есть), трасса пути, оси засады, превью выстрела (во что попадёт), зона
  расстановки, контрольная точка.

Что при этом **не** трогается: `Main`, `TankBench`, восемь корней и все
разделяемые модули, кроме перечисленных ниже точечных доработок картинки.

## 3. Доработки стенда, которых требует картинка правил

Каждая — своя задача со своим снимком, по правилам `godot/CLAUDE.md`. Полный
разбор по событиям, с ценой и порядком работ — [effects-plan.md](effects-plan.md).

| Что нужно правилам | Что есть | Доработка |
|---|---|---|
| Таран сдвигает жертву | `RamContacts` мнёт оба, `Halt` останавливает | режим «толчок»: жертве ставится нога на следующую клетку, таранящий доезжает до клетки цели; урон по классу выключен под `MatchRoot` |
| «Подбит»: корпус стоит, дыма мало, не горит | `Wreck` = взрыв + `Burning` | второе состояние `Wreck.Disabled` без детонации и пожара, с отметиной |
| «Уничтожен» всегда взрыв, соседи горят | `Kill`+`ProcRack`, `SheetBlast` | взрыв на клетке уже есть; добавить поджиг соседей событием |
| «Плывёт» / «Утоплен» | ватерлиния, `Wading` — только скорость | глубокая вода: корпус по башню (`Waterline` выше), утопленный — заглохший, без выхлопа |
| Дым на гексе | `ProcSmoke`/`Plumes` — только к танку и пожару | слой дыма на клетке: столб из `Plumes` в центре гекса, живёт по событию |
| Мина на гексе | `Cover.Minefield` без арта | спрайт мины (пайплайн: `assets/Images/…`), подрыв — `SheetBlast` малым `might` |
| Дорога, грязь | `Foundation.Sand` без карт с ним, дороги нет | текстуры `TerrainSet` для двух полов; буквы в алфавите карты |
| Вода двух высот | «вода находит уровень» через уровень клетки | высокая вода = вода на уровне 0: снять запрет `water.level`, где карта объявила высокую |
| Навес HM | `Shell` — прямая | траектория дугой для `HM` (второй режим `Shell.Advance`), трассер по дуге |
| Наведение корпусом TD/HM за шаги | `TurnHull` на стоянке по `TurnRate` | поворот на N×60° как событие `Turned` — уже покрыт `Moved`-логикой |
| Башня на шести осях с памятью | башня непрерывная, `TurretHoldsHeading` | снап `TurretFacing` к оси при событии `Fired`/`Overwatch`, выравнивание вперёд при `Moved` |
| Оси засады | нет | оверлей из `HexField` (полоса по клеткам, как `Highlight`) |
| Пожар по раундам | `Wildfire.Tick` в секундах | `Enabled=false` в бою, `Light`/`Told(Burnt)` по событиям |
| Лес под HT становится землёй | `Grove` сеет по `Cover` | `SetCover(None)` + пересев `Grove` клетки |

## 4. Этапы

Каждый этап заканчивается **играбельным** состоянием и тремя проверками:
`dotnet test` зелёный, `--selftest match` зелёный, снимок сцены боя в `out/`
руками просмотрен. Оценки — в рабочих днях одного разработчика с агентом,
грубо.

### M0. Скелет (2–3 дня)

- `Rules.csproj`, `Rules.Tests.csproj` (xUnit), `ProjectReference` из стенда,
  `NuGet.config` с nuget.org, проверка, что `dotnet build` стенда и `dotnet test`
  проходят и движок собирает проект с двумя сборками.

### M1. Движение и ход (5–7 дней)

Правила: units.md «Передвижение», match.md «Ход и раунд», «Структура хода»
п. 1–3, 7; field.md «Покрытия» (дорога +1, грязь стоп/1 шаг), «Рампа» (2 шага,
не останавливаться), лес останавливает; стены блокируют грань (HT — ломает
движением: только флаг, обвал — в M3); «Пас».

- `Reachable`: поиск по состояниям (клетка, курс) с ценой: вперёд 1, поворот 1,
  назад 1 без поворота и только первым/единственным движением, «влево-вправо в
  ноль» не считается, рампа только вдоль оси и только с запасом на выход,
  останавливающая клетка только последней, бонус дороги, старт в грязи/лесу = 1.
  Возвращает все пути равной цены — п. 2 GDD отдаёт выбор игроку.
- `Move` проигрывает путь поклеточно и порождает `Moved`/`Turned`; п. 4
  (эффекты по пути) — пока пустой хук, заполняется в M3.
- Ход/раунд: `Select` один юнит, `EndTurn`, `Pass`, смена стороны, счётчик
  раундов, тик поля как событие (пока пустой), правило «любой юнит, хоть тот
  же».
- Башня: выравнивается вперёд при движении, память между ходами.
- Стенд: подсветка достижимых, выбор пути щелчком по вариантам, трасса до
  подтверждения, HUD хода, hot-seat-экран передачи, проигрывание `Moved`
  ногами `Vehicle.Path`, снап башни.

**Тесты (примеры):** LT из грязи делает ровно 1 шаг; путь с одним оставшимся
шагом на рампу не заходит; назад через рампу нельзя; дорога даёт +1 только
если и старт, и финиш на дороге; стена на грани режет BFS; HT её проходит.

### M2. Прямая наводка (6–8 дней)

Правила: units.md «Пушка», «Цель выстрела», «Рикошет», «Броня», field.md
«Уровни и линия огня» (свой уровень, препятствия только между, стены по граням
в обе стороны), classes.md «Тяжёлый снаряд TD»; states.md «Подбит»,
«Уничтожен и взрыв» (соседи горят, цепь, стены сносятся, лес загорается);
match.md «Условия победы → Уничтожение».

- `LineOfFire.Trace(board, units, from, axis, shooterLevel, opts)` — один
  ответ на «что встретит снаряд»: клетка за клеткой по оси, стена на грани,
  юнит своего уровня, препятствие своего уровня; исключение гекса стрелка и
  цели; флаг тепловизора (M5). Заменяет расхождение `Gunnery.Solve`/`Track`.
- Зона брони: грань входа снаряда против курса корпуса → лоб/борт/корма;
  «строго больше»; подбитый — взрыв от любого попадания.
- Рикошет: только борт, только непробитие, зеркало «две грани одного борта
  меняются местами», та же мощь, один раз, второй цели минимальная дальность не
  нужна, свой поражается.
- TD: первое препятствие (танк или стена) — проход с −1, лес — нет.
- Минимальная дальность: 1 пустой гекс до цели-танка; стена и лес вплотную.
- Взрыв: шесть соседей своего уровня, цепь, лес, стены; «Уничтожен» на воде —
  утопленный тоже взрывается (Sunk появится в M3, сейчас как флаг).
- Пат: 4 раунда без выстрела по танку; победа уничтожением.
- Стенд: превью выстрела (во что попадёт), `ShellHit` через `TankTick.Shoot` с
  заданным исходом, `Ricochet` вторым снарядом, `Wreck.Disabled`, взрыв и
  цепь, экран результата.

**Тесты:** матрица пробития 5×5×3 зоны из classes.md целиком; таблица
рикошета для корпуса на N и её поворот на все 6 курсов; TD пробивает стену и
танк за ней, но не лес; танк на холме не виден с равнины; танк в крайнем гексе
рощи виден по свободной оси; выстрел по подбитому — взрыв без брони; цепь из
трёх подбитых; стены на гексе взорвавшегося исчезают.

### M3. Слои поля и состояния (6–8 дней)

Правила: field.md «Из чего состоит клетка», «Препятствия» (лес, пожар,
сгоревший лес, дым, стены, мины, вода), «Рампа» (мина на рампе, дым на рампе),
states.md «Горит», «Плывёт», «Утоплен», match.md таблица длительностей и тик
поля, п. 4 и п. 6 структуры хода, units.md «Тушение пожара».

- Слои клетки в `Board`: дым с таймером, пожар с таймером, мина, вода глубина ×
  высота; запрет леса на воде; расширение алфавита карты (буквы для дороги,
  грязи, мелкой/глубокой × низкой/высокой воды) и `MapFile`.
- П. 4 по пути: мина (подбит, трал передом — разминирует), вода (пожар гаснет;
  глубокая без ОПВТ — утоплен, с ОПВТ — плывёт), пожар (загорается), дым
  (рассеивается), горящий танк поджигает лес по пути, остановка на грязи/лесу.
- П. 6: все горящие танки игрока уничтожаются (взрыв), лес под остановившимся HT
  → земля (горящий — нет).
- Тик поля: пожар −1, при нуле сгоревший лес; распространение на соседний
  живой лес, стена блокирует; дым −1; первый тик в том же раунде.
- Стены: выстрел сносит грань, таран стены как действие, HT ломает движением.
- «Утоплен»: подбитый на глубокой воде.
- Стенд: слой дыма, спрайт мины, текстуры дороги и грязи, обвал грани
  по событию, `Wildfire.Enabled=false` и покраска по событиям, плывущий и
  утопленный корпус, горящий танк.
- Редактор: кисти новых полов и мин, запрет леса на воде, `MapRules`: лес на
  воде, стена на рампе (допустима), мина на воде (недопустима для заградителя,
  на карте — по решению автора; сейчас GDD молчит, флаг в undefined.md).

**Тесты:** пожар живёт ровно два тика и оставляет сгоревший лес, который не
загорается; дым под въехавшим танком исчезает; танк, загоревшийся на чужом ходу,
гибнет в п. 6 своего хода, если владелец ходил другим; трал задним ходом
подрывается; мина на рампе запирает подъём подбитым; ОПВТ плывёт, без — тонет;
вода тушит.

### M4. Таран, засада, навес, глаголы, способности (6–8 дней)

Правила: units.md «Таран», «Режим засады», «Активные способности»;
classes.md «Свободный порядок LT», «Секторная засада MT», «Бульдозер HT»,
«HM — Навес» целиком; field.md «Рампа → скатывается».

- Таран: вплотную, лбом, масса не меньше, запреты (занято, выше, край, любая
  стена на двух гексах — кроме HT, который их сносит), замещение, сдвиг с
  сохранением курса, вниз без рампы, скатывание с рампы вдоль оси, эффекты
  клетки обоим, подбитых таранить можно; таран стены как действие.
- Засада: действие п. 5, ось до первого препятствия, перепроверка при
  срабатывании, минимальная дальность, первый враг, по своим нет, снимается
  любым приказом/уничтожением/тараном, тратится выстрелом; отброшенный тараном
  считается вошедшим; MT — две соседние оси, один выстрел, башня доворачивается.
- LT: действие до движения (кроме засады), таран до движения и въезд на
  освободившийся гекс.
- HM: цели 3–5 по оси корпуса, любой уровень, порядок «танк забирает снаряд
  целиком», стены без танка все, мина подрывается, лес холостой, плывущий →
  утоплен.
- Тушение как действие не на горящем гексе.
- Стенд: `Pushed` — нога жертвы, `SlidDownRamp` — две ноги; оверлей осей засады;
  выстрел засады во время чужого движения — пауза проигрывателя на клетке входа;
  дуга снаряда HM; панель действий.

**Тесты:** таблица «кто кого таранит» 5×5; таран запрещён стеной на гексе
выталкивания, HT — нет; вытолкнутый на мину подбит; на рампу поперёк — запрет,
вдоль — скатился; засада стреляет по первому вошедшему и не по своему; MT
стреляет один раз при пересечении двух осей подряд; ось за дымом укорочена; LT
выстрелил и уехал; HM бьёт по гексу 4 через холм и лес, а по 2 — не может.

### M5. Апгрейды, контракт с метой, режим точки (5–6 дней)

Правила: upgrades.md (14 апгрейдов), match.md «Вход и выход боя»,
«Расстановка и первый ход», «Условия победы → Удержание точки».

- `UpgradeSet` и точки применения: трал (M3), ОПВТ (M3), шашка, зажигательный
  (лес горит, непробитый танк горит; у HM — мина миномёта), широкие гусеницы,
  задний ход (2 клетки, с поворотом, через рампу — нет), подбой, автотушение

  лебёдка (дистанция 2 по оси, гекс между пуст и без стен), заградитель (мина на
  соседний, не вода, не танк, не мина), ремкомплект (соседний свой подбитый →
  активен, утопленного нет, ходит со следующей активации, с рампы — вдоль оси),
  двойной поворот (первый поворот бесплатно), стабилизатор засады (не снимается

- `MatchSetup` (карта, отряды, апгрейды, игрок 1) и `MatchResult` (исход,

- Расстановка: зоны на карте, ряд по умолчанию, перестановка и разворот
  бесплатно, «В бой», втёмную с экраном передачи, жребий (единственная

- Режим точки: один гекс или гекс с соседями, перевес активных, −1 на тике
  не удерживающему (обоим при равенстве), N из карты, проигрыш при 0.
- Пат: без выстрела по танку **и** без смены удержания.
- Стенд: экран расстановки, зона и точка в оверлее, очки в HUD, экран результата
  с судьбой машин.

**Тесты:** каждый апгрейд — отдельный класс тестов «с ним / без него»; автотушение
не срабатывает у активированного; лебёдка через ось засады вызывает выстрел;
контроль точки при равенстве никто; пат считает смену удержания.

## 5. Порядок тестов и что считается доказательством

Три контура, каждый про своё:

1. **`dotnet test` (Rules.Tests)** — правила. Один тестовый класс на раздел
   GDD, имя теста — фраза правила. Табличные тесты для матриц (пробитие,
   массы, рикошет). Сценарные тесты — карта ASCII в тесте той же буквенной
   сеткой, что `maps/*.json`, чтобы сценарий читался глазами. Тест
   детерминизма: реплей даёт те же события. Цель — покрыть каждый пункт DoD в
   `contradictions.md`/`undefined.md` хотя бы одним тестом; это и есть готовая
   спецификация из 20 разделов с чекбоксами.
2. **`--selftest match`** — адаптер и проигрыватель: доска стенда совпадает с
   `Board` (поклеточно), после проигрывания событий каждый `Vehicle` стоит на
   клетке своего `Unit` с тем курсом, `Wreck` соответствует `Condition`,
   события не теряются и не дублируются, `--instant` проигрывает партию из
   реплея до конца без исключений.
3. **Снимок** — картинка: по правилу стенда никакой успех не рапортуется по
   коду возврата. Для каждого этапа один эталонный сценарий с `--capture`.

## 6. Риски и открытые решения

**Решения, которых план ждёт от автора (остальное — рабочие допущения):**

1. **Отдельная сборка `Rules` или всё в одной?** План — отдельная (см. 2).
   Цена: два csproj, `NuGet.config`, sln в git. Выигрыш: `dotnet test` без
   движка и чистая граница. Рекомендую отдельную.
2. **Число N очков** (U-01 открыт). Для карты PT предлагаю N = 10 как
   настроечное, записать в карту и в undefined.md как «принято для PT».
3. **Мина на воде на карте** — GDD запрещает только заградителю; редактору
   разрешить или нет? Допущение: запрещено везде (мина требует дна).
4. **Стрельба между уровнями через стену на кромке холма**: стена на грани
   между гексами разных уровней — блокирует ли она навес HM? GDD: миномёт
   поверх всего. Допущение: не блокирует ничего у HM вообще.
5. **Что видно при hot-seat в момент срабатывания засады** (враг ходит,
   выстрел засады — анимация на его экране): допущение — показывать сразу.

**Риски реализации:**

- **Проигрыватель событий** — самый тонкий кусок стенда: `TankTick` ведёт
  движение непрерывно и решает попадание при вылете; правилам нужно задать
  исход заранее. Швы для этого есть (`Launch`, `Send(Level)`), но рикошет как
  второй снаряд и таран как сдвиг — новые режимы `TankTick`, и они должны
  включаться флагом корня, не ломая `Main`/`TankBench`. Проверка: полный
  `--selftest` остаётся на тех же 3 известных падениях (деревья `Grove`).
- **`SelfTest.cs` бинарен для git** (NUL-байт, см. память проекта): новые
  проверки писать LF и не трогать соседние строки.
- **Ловушка запуска** (`project.godot`, `.csproj` переписываются движком):
  любой прогон сцены боя — под хук `godot_status.py`; `run/main_scene`
  возвращать.
- **Расхождение LoS**: `Gunnery.Solve` без высоты и `TankTick.Track` с высотой
  останутся у стенда как есть; в бою решает `Rules.LineOfFire`, стенду
  передаётся готовый исход. Не пытаться чинить стенд — это его свойство (U-15).
- **Арт**: мина, дым на клетке, дорога, грязь, дуга HM — задачи пайплайна и
  `TerrainSet`, а не правил; до их появления сцена боя рисует заглушки
  (цветной гекс), и это допустимо для плейтестов на бумаге.
- **Объём `Main.cs`**: спавн танков (`_Ready` строки 2149–2360) надо вынести в
  общий модуль до M0, иначе `MatchRoot` начинается с третьей копии (сейчас их
  две: `Main` и `TankBench`).
