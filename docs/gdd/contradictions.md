# Внутренние противоречия GDD

Список мест, где [GDD](index.md) утверждает два несовместимых правила или
опирается на текст, которого в документе нет. Каждый пункт закрывается правкой
черновика, а не обсуждением. Флаг `DoD` описывает, что должно быть верно в
тексте, чтобы пункт считался закрытым.

Статус: `[ ]` открыт, `[x]` закрыт. Дата закрытия и ссылка на раздел черновика
ставятся в строке `Закрыто:`.

---

## C-01. Пожар и танк: два условия загорания

**Где:** «Препятствия → огонь\пожар» и «Состояния → Горит».

**Противоречие.** В препятствиях танк загорается, если **заканчивает ход** на
гексе с пожаром. В состояниях горит тот, кто **проехал через** горящий гекс.
Это разные условия: проезд через пожар без остановки по первому правилу
безопасен, по второму нет.

**Решение (2026-09-05).** Танк загорается, если проезжает через гекс с пожаром
и/или останавливается на нём. Записано в «Препятствия → огонь\пожар», в
«Состояния → Горит» стоит ссылка.

**DoD**
- [x] В черновике одно условие загорания, записанное один раз, во втором месте ссылка.
- [x] Условие покрывает проезд через гекс и остановку на гексе.
- [x] Стояние на гексе, который загорелся под танком между ходами владельца: танк загорается и ждёт хода владельца. Владелец либо тратит активацию на спасение, либо жертвует танком ради хода другим. Гамбит записан явно.

Закрыто: 2026-09-05, GDD «Препятствия → огонь\пожар» и «Состояния → Горит».

## C-02. Пожар как мгновенная смерть

**Где:** «Состояния → Горит», «Структура хода» п. 4–6.

**Противоречие.** Танк загорается в п. 4, «если закончит ход горящим, будет
уничтожен» в п. 6. Спасает только тушение в п. 5. То есть пожар стоит ровно
выстрела и никогда не переживает ход. Это может быть намеренным дизайном, но
текст читается как незамеченный баг: активная способность «тушение» описана
как одна из многих, а не как единственный способ выжить.

**Решение (2026-09-05).** Это намеренный дизайн. Пожар стоит одну активацию:
горящий танк живёт до конца хода владельца, и владелец либо тратит ход на его
спасение, либо жертвует им. Проверка уничтожения в п. 6 идёт по всем танкам
игрока, а не только по активированному.

**DoD**
- [x] Явно записано, переживает ли горящий танк конец хода. У «Горит» стоит формула «пожар это цена в одну активацию».
- [x] Способы тушения: активное действие вместо выстрела и/или въезд на гекс с водой. Дым и соседние юниты не тушат. Тушить можно только не на горящем гексе. Въезд в воду без ОПВТ по-прежнему топит (см. C-03).
- [x] Пожар на чужом ходу: танк загорается от распространения и ждёт хода владельца.

Закрыто: 2026-09-05, GDD «Состояния → Горит», «Активные способности → Тушение пожара».

## C-03. Вода: непроходима и одновременно топит

**Где:** «Препятствия → вода».

**Противоречие.** Вода «непроходима для большинства танков», но «если танк
оказывается в воде, он утоплен» и «если горел, пожар затухает». Утопленному
пожар безразличен. Оба правила имеют смысл только если танк способен попасть в
воду: с ОПВТ или от толкания. Толкания в правилах нет, ОПВТ не описан.

**Решение (2026-09-05).** Воды две. Брод (уровень 0) проходим для любого танка и
ни на что не влияет, кроме пожара. Глубокая вода (уровень −1): в неё съезжают по
рампе по своей воле или падают от тарана без рампы. С ОПВТ танк «Плывёт», без
ОПВТ «Утоплен»: двигатель залит. Тушение водой оставлено для обеих вод, для
утопленного оно безразлично.

**DoD**
- [x] Перечислены все способы оказаться в воде: рампа по своей воле, таран без рампы.
- [x] Для каждого способа указан исход: брод — проходит, глубокая с ОПВТ — плывёт, глубокая без ОПВТ — утоплен.
- [x] Правило про тушение водой оставлено, с оговоркой про утопленного.
- [x] Брод введён как отдельный тип. **Пересмотрено в U-03 (2026-09-05):** брод теперь не «мелкая вода уровня 0», а рампа, ведущая в мелкую низкую воду, как на стенде. У воды два признака: глубина и высота.

**Открылось после решения** (новые состояния «Плывёт» и «Утоплен»):
- [x] Плывёт: стреляет, цель, броня как на суше, перекрывает линию огня. Уточнено, что дно воды на −1, а поверхность на 0: пустая вода огонь не перекрывает, танк в ней перекрывает.
- [x] Утоплен: цель, взрывается как подбитый, блокирует движение и линию огня.
- [x] Таран в воду: таран сдвигает цель на гекс по направлению удара (C-06), в воду она падает без рампы. Таранящий занимает гекс цели, поэтому на краю оказаться не может.
- [x] Выезд плывущего из воды только по рампе. Берег без рампы — стена в уровень, как у оврага. Следствие: столкнутый тараном в водоём без рампы танк с ОПВТ плывёт, но выехать не может, и это часть цены за подставленный борт.

**Пересмотрено 2026-09-11** ([docs/swim-plan.md](../swim-plan.md)): въезд в глубокую воду **не требует рампы** — танк съезжает с любого соседнего гекса берега, уровень вниз, как с пристани (с ОПВТ плывёт, без ОПВТ утоплен); рампа остаётся единственным выездом. Берег без рампы — по-прежнему стена, но только вверх. На стенде это прыжок со всплеском и качкой, выезд — маршрут кругом через рампу.
- [x] GDD «Препятствия → вода» и «Состояния → Плывёт» поправлены.

Закрыто: 2026-09-05, полностью; пересмотр въезда 2026-09-11. GDD «Препятствия → брод / глубокая вода», «Состояния → Плывёт / Утоплен».

## C-04. Стены на гранях не запрещают проезд

**Где:** «Препятствия → кирпичные стены», «Передвижение», «Активные способности → таран стен».

**Противоречие.** Движение разрешено «по пустым клеткам». Стена стоит на грани,
а не на клетке, поэтому по букве правил через неё можно ехать. Тогда «таран
кирпичных стен» ничего не даёт.

**Решение (2026-09-05).** Стена блокирует проезд через грань и выстрел через
грань в обе стороны. Снаряд тратится на стену и не летит дальше. Таранить может
любой юнит: действие п. 5 вместо выстрела, проезд через грань на соседний гекс,
стена разрушена, танк цел. Миномёт стреляет поверх стен.

**Уточнение (2026-09-05).** Первая формулировка «таран тратит все MP» отозвана
автором: таран стены это действие, а не движение.

**DoD**
- [x] Стена блокирует проезд через свою грань.
- [x] Стена блокирует выстрел через грань в обе стороны.
- [x] Выстрел в стену тратится целиком, снаряд дальше не летит.
- [x] Таран стены: любой юнит, действие вместо выстрела, проезд на соседний гекс, стена разрушена, танк цел.

**Следствия, закрытые тем же решением:**
- [x] Таран стены это действие (п. 5). Выстрела в этот ход нет.
- [x] Срикошетивший снаряд разрушает стену и тратится на неё.
- [x] Ось засады обрезается неразрушенной стеной.
- [x] Взрыв подбитого танка сносит все стены на гранях своего гекса. Записано и в «Состояния → Уничтожен»; в U-08 остаются танки и лес.

Закрыто: 2026-09-05, полностью. GDD «Препятствия → кирпичные стены», «Активные способности → Таран кирпичных стен», «Состояния → Уничтожен».

## C-05. Мина в обход состояния «Подбит»

**Где:** «Препятствия → мины», «Состояния».

**Противоречие.** Все прочие поражения проводят танк через «Подбит». Мина
уничтожает сразу, одинаково LT и HT, без брони. Плюс не сказано, видна ли мина
игроку. Для игры без кубиков скрытая мина это чистая случайность.

**Решение (2026-09-05).** Мины видны всегда: это ограничитель движения и
ловушка для вытолкнутого тараном. Исход «Подбит», только для танка на гексе,
мина израсходована. Срабатывает при проезде и при остановке. Трал это апгрейд
из прокачки, работает только передом: задним ходом или вытолкнутый боком танк с
тралом подрывается.

**DoD**
- [x] Мина видна обоим игрокам всегда.
- [x] Исход «Подбит», соседей не трогает, мина израсходована.
- [x] Срабатывает при проезде и при остановке.
- [x] Трал: апгрейд из прокачки, разминирует проездом без лишних шагов, только передом.

**Следствия:**
- [x] Для C-06 решён один пункт: эффекты клетки применяются к отброшенному тараном, как при обычном въезде (мина явно; пожар и рампа по аналогии — подтвердить там).
- [x] Раздел «Апгрейды» создан в GDD: определение, отличие от активной способности, таблица с тралом и ОПВТ. Ёмкость, цена и состав списка ведутся в U-11.

Закрыто: 2026-09-05, полностью. GDD «Препятствия → мины», «Апгрейды».

## C-06. Таран против правила «не сквозь юниты»

**Где:** «Передвижение», «Активные способности → таран танка».

**Противоречие.** Движение «никогда сквозь другие юниты», таран требует въезда в
занятую клетку. Что делает таран, не сказано: толкает, подбивает, мнёт по классу.

**Решение (2026-09-05, частичное).** Таран это замещение: таранящий въезжает на
гекс цели, цель отбрасывается на соседний гекс по направлению тарана. Отброшенный
в глубокую воду падает без рампы.

**Решение (2026-09-05).** Таран это действие вместо выстрела, только вперёд,
разгон не важен. Танк только сдвигается, повреждений нет. Нельзя, если за целью
юнит, холм или край карты. Эффекты клетки применяются к отброшенному в обычном
виде. Кто кого сдвигает, задано таблицей масс по аналогии с бронёй и оружием.

**DoD**
- [x] Таран описан как исключение из правила движения: въезд на занятый гекс с вытеснением.
- [x] Условие: вплотную, только вперёд, разгон не важен, действие п. 5.
- [x] Исход: только сдвиг, повреждений нет. Расхождение со стендом записано: там таран мнёт корпуса ([../combat.md](../../godot/docs/combat.md)), правила этого не делают.
- [x] Гекс за целью занят, холм или край: таран невозможен. Остальное можно, в воду и овраг цель падает без рампы.
- [x] Таран это действие (п. 5), как и таран стены.
- [x] Эффекты клетки для отброшенного применяются в обычном виде, таранящий тоже получает эффекты нового гекса.

**Допущения, подтверждённые автором (2026-09-05):**
- [x] Массы TD = II и HM = I по корпусу.
- [x] Правило «масса таранящего не меньше массы цели».
- [x] Стены: строже, чем предполагалось. Любая стена на гексе цели или на гексе выталкивания запрещает таран, не только на пути удара. Танк и стену одним тараном не берут.
- [x] Овраг: отброшенный падает без рампы, выезд из оврага только по рампе. Записано и у оврага в «Препятствиях».
- [x] Отброшенный сохраняет направление корпуса.

Закрыто: 2026-09-05, полностью. GDD «Активные способности → Таран», «Препятствия → овраг».

## C-07. Пункты 2 и 3 хода: выбор гекса против трат шагов

**Где:** «Структура хода» п. 2–3.

**Противоречие.** П. 2 говорит «выбирает гекс для движения», п. 3 «тратит шаги».
Грязь останавливает немедленно, засада срабатывает при пересечении оси,
значит движение пошаговое, а не «до цели». Две модели ввода в одном ходе.

**Решение (2026-09-05).** Путевая модель. UI подсвечивает достижимые гексы с
учётом MP и поверхности, игрок указывает один, путь строится по правилам.
Эффекты применяются по ходу пути, останавливающий эффект обрывает его. Отмена
после подтверждения невозможна.

**DoD**
- [x] Оставлена путевая модель, п. 2–4 структуры хода переписаны под неё.
- [x] Отмена после подтверждения запрещена, путь проигрывается целиком.

**Следствия, закрытые автором (2026-09-05):**
- [x] При равной стоимости путь выбирает игрок. UI показывает трассу всегда, до подтверждения.
- [x] Танк заканчивает путь направлением, каким пришёл. Разворот после прибытия за оставшиеся MP, шаг за 60°, это часть движения, а не действие п. 5.
- [x] Засада, не подбившая танк, путь не обрывает: танк доезжает до конца.

Закрыто: 2026-09-05, полностью. GDD «Структура хода» п. 2–4.

## C-08. «Ход» не определён: активация или раунд

**Где:** весь документ; критично для пожара, дыма, засады.

**Противоречие.** Структура хода двигает **один** юнит и передаёт ход сопернику.
Значит «ход» это одна активация. Тогда пожар живёт 2 активации и распространяется
каждую, лес выгорает за шесть активаций, дым живёт меньше одного круга стола.

**Решение (2026-09-05).** Ход это активация одного юнита, любого, хоть одного и
того же каждый ход. Раунд это ход игрока 1 плюс ход игрока 2, всегда два хода.
Тик поля в конце раунда, то есть после каждого хода игрока 2. Состояния
танков живут по ходу владельца, эффекты поля по раунду. Таблица длительностей
в черновике, раздел «Ход и раунд».

**Почему тик в конце раунда.** Раунд единственная единица, одинаковая для обоих
игроков. Тик после каждой активации делал бы длительность дыма зависимой от
очереди хода. Тик в конце раунда делает распространение пожара предсказуемым в
пределах раунда.

**DoD**
- [x] Введены термины «ход» и «раунд», раздел «Ход и раунд» перед структурой хода.
- [x] Пожар и дым переписаны в раундах, «Горит» привязан к ходу владельца, таблица длительностей составлена. Засада в таблице стоит как нерешённая (U-06).
- [x] Тик поля в конце раунда, с правилом счётчика: −1 на каждом тике, снятие при нуле, первый тик в конце того же раунда.

**Уточнение автора (2026-09-05).** Первая запись раунда как «все юниты сходили по
разу» была ошибкой записи, а не решением: она тянула за собой ограничение «один
раз за раунд» и правило доигрывания при неравном числе юнитов. Оба сняты.
Раунд это пара ходов, юнит любой.

**Следствие, которое остаётся:** игрок 2 всегда ходит последним перед тиком и
первым видит его результат игрок 1. Это постоянная асимметрия, как право
первого хода в шахматах, и решается в U-14 вместе с вопросом, кто ходит первым
и чем это компенсируется.

Закрыто: 2026-09-05, полностью. GDD «Ход и раунд», «Структура хода» п. 1.

## C-09. Копипаста и следы рулбука

**Где:** «огонь\пожар», «дым», «Броня», «Передвижение», «Препятствия».

**Противоречие.** У пожара и дыма написано «деревья перекрывают обхор», у дыма
ещё и «поверх гексов с деревьями». «Броня» ссылается на «серые стрелки»
картинки из Tank Chess, которой нет. Земля стоит под заголовком «Препятствия»,
хотя ни на что не влияет. Юнит по тексту то «он», то «она», это след слова
«фигура».

**Решение (2026-09-05).** Пожар рождается только на гексе с деревьями: взрыв
танка, выстрел по гексу, распространение. Дым остаётся после пожара либо ставится
дымовой шашкой. Броня: лоб одна грань, борта по две с каждой стороны, корма одна.
Земля, дорога, грязь это покрытия. Юнит мужского рода.

**DoD**
- [x] Пожар и дым описаны своими словами, с источниками. Выстрел по лесу поджигает его, снаряд тратится, по аналогии со стеной.
- [x] Зоны брони описаны таблицей по граням гекса: 1 + 4 + 1. Ссылка на картинку убрана.
- [x] Раздел «Покрытия» выделен перед «Препятствиями», с определением того и другого.
- [x] «Юнит» везде мужского рода, «Obstacle» убрано.

**Следствия:**
- [x] U-09 продвинут: после пожара остаётся дым. **Отменено в U-09 (2026-09-05):** после пожара остаётся сгоревший лес, дыма нет.
- [x] U-10 продвинут: источник дыма теперь один — шашка. Параметры шашки открыты там.

Закрыто: 2026-09-05, полностью. GDD «Покрытия», «Препятствия → деревья / пожар / дым», «Броня», «Передвижение».

## C-10. Статус относительно GDD_OBSOLETE

## C-11. Рикошет: проза против собственной таблицы

**Где:** «Рикошет» в [units.md](units.md).

**Противоречие.** Текст описывает отражение словами: «составляющая „в сторону
борта“ сохраняется, составляющая „вдоль корпуса“ меняет знак». Таблица под этой
же фразой утверждает обратное — корпус на N, снаряд пришёл с NE, ушёл на SE, то
есть знак сменила составляющая **поперёк** корпуса, а вдоль сохранилась. Прочитанное
по прозе правило даёт NE → NW: снаряд ушёл бы через противоположный борт, чего
не бывает.

**Решение (2026-09-08).** Права таблица: бортовая плита — зеркало, а зеркало
меняет знак составляющей по своей нормали и сохраняет составляющую вдоль себя.
Фраза перевёрнута. Стенд считал так с самого начала (`Vehicle.Graze`,
`2·outward − from`), и ось вылета теперь одна функция — `Gunnery.Deflect`,
чья самопроверка утверждает все четыре строки таблицы.

**DoD**
- [x] Проза и таблица говорят одно и то же.
- [x] Названо, что это отражение от плоскости, а не отдельное правило.

Закрыто: 2026-09-08, полностью. GDD «Юниты → Рикошет».
